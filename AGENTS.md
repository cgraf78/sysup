# AGENTS.md

## About

`sysup` upgrades Arch, Debian, and Ubuntu hosts through one command, then
restarts affected services and checks package and systemd state. It runs
real package managers as root, so tests must never reach one.

## Layout

- `bin/sysup`: the only public command. It detects the host family and
  `exec`s the matching backend.
- `lib/sysup/`: the private implementation (see its README). `archup` and
  `debup` are the backends; `common.sh` owns flag parsing and the
  upgrade, check, and restart ordering; `detect.sh` the family vocabulary;
  `systemd.sh` affected units, failed units, and deferred restarts.
- `docs/design.md`: the backend hook contract and run ordering.
- `test/run` runs `sysup-test`, `archup-test`, and `debup-test`, each in its
  own Bash process; `test/lib/test.sh` holds the assertions.
- `support/install-checkout.sh`: the repo-owned install delegate.

## Invariants

- `bin/sysup` and `lib/sysup/detect.sh` must stay Bash 3.2-compatible, so an
  unsupported macOS host still gets `sysup --help`. The backends need Bash 4.
- The package manager's exit status stays final. Later check and restart
  failures are reported but never replace it.
- Autoremove runs only after a clean upgrade.
- Hook-contract changes update `docs/design.md` in the same change.

## Testing

- Local: `test/run`. It also runs ShellCheck over the programs listed in
  `.github/shellcheck-files.txt` when `shellcheck` is installed.
- CI: `SYSUP_SKIP_SHELLCHECK=1 test/run` on the shared shell matrix (profile
  `base`), a separate ShellCheck job, and a `Stock macOS Bash 3.2` job that
  runs `PREFIX=$tmp /bin/bash install.sh` and then
  `/bin/bash $tmp/bin/sysup --help`. A `Required` job gates both.
- The Bash 3.2 job covers only install and `--help`; it does not prove other
  dispatcher paths.

## Test isolation

- Never invoke a real package manager, `sudo`, or `systemctl`. Backend suites
  source the private files and replace those commands with shell-function
  fixtures; `sysup-test` uses fake executables on `PATH`.
- Point host state at temporary paths: `SYSUP_OS_ROOT` for the `/etc`
  release files that family detection reads, `SYSUP_STATE_DIR` and
  `SYSUP_BOOT_ID_FILE` for deferred restarts. `SYSUP_TEST_KERNEL` drives
  `sysup-test`'s fake `uname`.
- Use synthetic package, unit, and account names only.

## CI and generated files

- CI's ShellCheck job fails on any shell program missing from
  `.github/shellcheck-files.txt` (untracked files included) and on stale rows;
  local `test/run` does not detect this. Before pushing, run
  `bash <actions@lock>/.github/actions/shellcheck-inventory/run.sh "$PWD" .github/shellcheck-files.txt`
  from a cgraf78/actions checkout at the SHA in `.github/cgraf78-actions.lock`.
- `install.sh` is generated by the cgraf78/actions checkout installer and
  byte-checked by the `cgraf78/actions sync` job; never hand-edit it. After
  changing `scripts/checkout-installer.conf`, run
  `consumer-ci/sync.sh <this checkout>` from cgraf78/actions at the locked SHA.
- `.github/cgraf78-actions.lock` and every `uses: cgraf78/actions/...@<sha>`
  move together, only via `consumer-ci/sync.sh`.
- `test/sysup-test` pins the text of the `Required` job in `test.yml`; edit
  both together.
- `retry-infrastructure.yml` keys on the workflow name `Tests`; don't rename
  it.
